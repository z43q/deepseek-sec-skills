# Web 漏洞定向挖掘方法论

不依赖扫描器和 CVE 指纹库。核心思想：**通过构造 HTTP 请求与后端对话，从响应中推断业务逻辑，发现非预期行为。**

> 配套文档：[工具安装指南](references/INSTALL.md) | [操作手册](references/WORKFLOW.md)

## 与一般挖洞的本质区别

| | 传统方法 | 本方法 |
|---|---------|------|
| 武器 | CVE 库、nuclei 模板 | HTTP 响应推理 |
| 发现方式 | 扫描匹配已知指纹 | 对话发现逻辑缺陷 |
| 打的漏洞 | 框架/中间件的已知错误 | 开发者此刻代码里的逻辑错误 |
| 提交证据 | CVE 编号 + 截图 | 一条 curl + 响应 |

## 核心循环：定向 Fuzzing

```
1. 抓正常HTTP请求        → 浏览器/抓包拿到模板
2. 改造参数              → 只改会"被后端执行"的参数
3. 发送 + 读响应         → HTTP状态码/错误信息/返回数据
4. 推断后端行为          → 从响应中读出处理规则
5. 修正 Payload          → 根据推理调整
6. 循环直到触发非预期行为  → 漏洞
```

**漏洞证据 = 一条 curl 命令 + 异常响应**。审核者 5 秒可确认。

## 三层漏斗：判断请求走到了哪

```
所有 HTTP 请求
  ↓ 返回 403/503/"JS Challenge"/连接超时？
  → WAF 拦截 ✗  换子域/降级HTTP版本/浏览器渲染绕过
  ↓ 返回 200 但内容为"请登录"/"auth required"/业务error_code？
  → 需要认证 ✗  换不需要登录的公开功能
  ↓ 返回 200 + 业务数据？
  → 进入攻击循环 ✓  改参数字段看能否越权
```

## 读响应的三个层次

| 层次 | 响应信号 | 含义 | 行动 |
|:--:|------|------|------|
| 1 | 403/503/超时/JS Challenge | 没到后端 | 绕过 WAF |
| 2 | 200 + "请登录"/error_code:100xxx | 到了后端，要认证 | 找公开功能 |
| 3 | 200 + 业务数据 | 到了后端，有返回 | 改参数测越权 |

- `error_code:100001` vs `error_code:401` — 前者是后端业务逻辑在运行，后者是网关拦截
- `Content-Length` 不同 → 处理路径不同
- 错误消息的措辞变化 → 参数在不同代码分支中被处理

## 三条铁律

**铁律 1：只打不需要登录的端点。** 登录后的 API 在拿到账号前不碰。

**铁律 2：一次只改一个参数。** 改了多个参数就不知道是哪个触发的。

**铁律 3：响应中的每一行都是线索。** 状态码、错误码、响应长度、响应头的差异都是在和后端对话。

## 攻击面优先级

| 优先级 | 功能类型 | 漏洞类型 | 原因 |
|:--:|------|------|------|
| 1 | 搜索框 | 反射型 XSS、SQL 注入 | 天然公开，用户输入必被处理 |
| 2 | 注册/找回密码 | 短信轰炸、验证码绕过、任意注册 | 无认证门槛 |
| 3 | 评论/反馈/咨询 | 存储型 XSS | 内容会展示给其他用户 |
| 4 | 文件上传 | 任意文件上传、路径穿越 | 头像/附件入口常被忽略 |
| 5 | 短链接/外部跳转 | Open Redirect | 常用于钓鱼链 |
| 6 | OAuth 回调 | redirect_uri 越权 | 第三方登录流程复杂 |
| 7 | 公开 API | 越权、信息泄露 | 无需认证的数据接口 |

## 漏洞证据标准

```bash
# 一条 curl = 完整的漏洞证明
curl -sk 'https://target.com/api/user/info?id=2' \
  -H 'Cookie: session=xxx'    # 用自己的合法 session

# 响应：返回了其他用户的数据
{"code":0,"data":{"name":"其他用户","phone":"138****1234"}}
```

不需要扫描器报告、不需要 CVE 编号、不需要截图。审核者从一条命令和响应即可判断。

## 工具链

| 阶段 | 工具 | 用途 |
|------|------|------|
| 侦察 | whatweb / nmap / crt.sh | 技术栈指纹、子域枚举 |
| 抓包 | mitmproxy / BurpSuite | 获取正常 HTTP 模板 |
| 发送 | curl / Python requests | 构造并发送恶意请求 |
| 绕过 | Chromium headless | JS Challenge WAF 绕过 |
| 代理 | 代理池 | IP 轮换防封禁 |
| 分析 | jq / grep / python | JSON 响应解析、模式提取 |

## 禁止行为

- 不对单个端点连续发超过 5 个请求
- 不提交"403 目录存在""服务器默认页""sitemap 泄露"等侦察噪音
- 不为了凑产出降低漏洞标准
- 不在 WAF 全挡且 API 全认证的目标上持续投入

## 适用场景

- SRC 漏洞挖掘（人工辅助，非自动化扫描）
- 渗透测试中的业务逻辑漏洞发现
- API 安全评估中的越权测试
- 对 WAF 保护目标的绕过测试
